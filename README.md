# SmartDNS — персональный Smart DNS / geo-unblock

Self-hosted платформа: вы указываете на устройстве свой DNS, выбранные сервисы
идут через вашу ingress-ноду и зарубежную egress-ноду, всё остальное — напрямую.
Панель управляет множеством нод, но её отказ не останавливает трафик.

```
телефон ──DNS──▶ ingress ──туннель──▶ egress ──▶ сервис        управляемые домены
телефон ──DNS──▶ Unbound ──рекурсия──▶ настоящий IP ──▶ сайт   всё остальное
```

Конечный сервис видит IP egress-ноды. TLS между устройством и сервисом не
вскрывается: ingress считывает только SNI и передаёт байты как есть.

## Содержание репозитория

| Каталог | Что внутри |
|---|---|
| `panel/` | control plane: API, компилятор ревизий, планировщик, веб-панель |
| `agent/` | агент ноды: регистрация, получение ревизий, атомарное применение, откат |
| `node/` | data plane: DNS frontend, SNI proxy, egress relay, Unbound, Compose-профили |
| `shared/` | общий контракт: нормализация доменов, артефакты, PKI, туннель, метрики |
| `deploy/` | Compose панели и полный стенд `deploy/examples/lab` |
| `scripts/` | установка, обновление, резервное копирование, сквозной тест |
| `docs/` | эксплуатация, безопасность, API, ADR, runbooks |
| `tests/` | интеграционные тесты и заглушки для стенда |

## Быстрый старт за пять минут (локальный стенд)

Нужен только Docker с Compose v2.

```bash
git clone <репозиторий> smartdns && cd smartdns
make lab-up          # поднимает панель, ingress, egress и заглушки, прогоняет проверки
```

Скрипт печатает результат 21 проверки, затем оставляет стенд работать:
панель на `http://localhost:8080`, вход `admin@lab.local` / `labadminpassword`.

Остановить: `make lab-down`.

> Стенд запускается с `LAB_MODE=1`: egress-ноде разрешено обращаться к приватным
> адресам, потому что заглушки живут внутри docker-сети. В production этот режим
> отключает защиту от open proxy — не включайте его.

## Установка на своё оборудование

### 1. Панель

```bash
curl -fsSLO https://RELEASE/install-panel.sh
curl -fsSLO https://RELEASE/install-panel.sh.sha256
sha256sum -c install-panel.sh.sha256      # сначала проверьте, потом запускайте
less install-panel.sh
sudo bash install-panel.sh --public-url https://panel.example.net --admin-email you@example.net
```

Скрипт проверяет ОС, Docker, порты и место, показывает план до изменений,
генерирует секреты, применяет миграции и ждёт готовности. Повторный запуск
идемпотентен и не перезаписывает существующий `.env`.

UI слушает 8080 по HTTP — держите его за TLS-прокси или ходите через SSH-туннель
(`ssh -L 8080:localhost:8080 …`). Входного шлюза агентов у панели больше нет:
она сама подключается к нодам, поэтому должна доставать до их порта 3333.

### 2. Ноды

Модель push: панель сама подключается к ноде на её порт **3333**. В панели:
**Ноды → Добавить ноду**, укажите роль и адрес управления, скопируйте команду —
в ней уже бандл (как `SECRET_KEY` у remnanode: сертификат ноды + якорь CA + пин
панели).

```bash
sudo bash install-node.sh --role ingress --bundle <BASE64> --panel-ip <IP-панели>
```

Нода поднимается сервером и ждёт панель — наружу не звонит. Порт 3333 откройте
фаерволом **только для IP панели**; сверх этого нода пускает лишь клиента с
сертификатом панели. Бандл провизионит один раз, дальше игнорируется.

**Рекомендуемая раскладка ingress-ноды — два публичных IP:**

| Назначение | Привязка |
|---|---|
| Обычный DNS | `DNS_IP:53` UDP и TCP |
| DoT | `DNS_IP:853` TCP |
| DoH | `DNS_IP:443` TCP |
| Управляемый HTTPS | `PROXY_IP:443` TCP |

С одним IPv4 DoH и прокси не могут одновременно занять TCP/443 — понадобится
SNI-мультиплексор перед ними либо перенос DoH на другой порт. Подробности и
готовый конфиг: [`OPERATIONS.md`](OPERATIONS.md#один-ip-и-порт-443).

### 3. Первый сервис

**Быстрый старт** в панели — чек-лист из семи шагов:
набор правил → сервис → группы → сборка ревизии → выкат → профиль устройства → проверка.

### 4. Устройство

**Устройства → Новый профиль.** Панель выдаёт `.mobileconfig` для Apple или
инструкцию в Markdown для остальных платформ.

| Платформа | Как |
|---|---|
| Android | Настройки → Сеть и интернет → Частный DNS → имя хоста DoT |
| iOS / macOS | Установить `.mobileconfig`, затем Настройки → Основные → VPN и управление устройством |
| Windows 11 | Параметры → Сеть → адаптер → DNS-серверы → Шифрование: только DoH, шаблон из профиля |
| OpenWrt | `https-dns-proxy` с `resolver_url` из профиля либо `stubby` для DoT |

Проверка после настройки:

```bash
dig +short <управляемый-домен>   # адрес ingress-ноды
dig +short example.org           # настоящий адрес
curl -s https://<управляемый-домен>/ -o /dev/null -w '%{remote_ip}\n'
```

## Что система делает и чего не делает

**Делает.** TCP/TLS насквозь для выбранных доменов (прежде всего 443), обычный
DNS, DoT и DoH, синтез A (и AAAA после проверки IPv6-пути), определение домена
по SNI без вскрытия TLS, защищённый туннель ingress→egress, группы нод с
резервированием, импорт списков из GitHub и HTTPS с diff и подтверждением,
неизменяемые ревизии с атомарным применением и откатом, автономность нод при
отказе панели.

**Не делает и не обещает.**

- **HTTP/3 (QUIC).** По умолчанию UDP/443 отклоняется, браузер откатывается на
  TCP. Проксирование UDP включается только после сквозной проверки конкретного
  сервиса — наличия опции недостаточно.
- **Encrypted ClientHello.** Если внутренний SNI зашифрован, восстановить
  назначение нечем. Такие сервисы не объявляются поддерживаемыми, а трафик с
  неопознанным назначением отклоняется, а не отправляется в «прокси по умолчанию».
- **DNSSEC для подменённых ответов.** Синтезированный ответ не может нести
  подпись origin, и флаг AD на нём никогда не выставляется. Обычные домены
  валидируются Unbound полноценно.
- **Гарантированный failover по двум DNS-адресам.** ОС может использовать оба
  сервера или долго держаться за первый.
- **Приложения с IP pinning, собственным DNS или certificate pinning к
  нестандартному потоку.**
- **Обход региональных ограничений на уровне аккаунта.** Если сервис привязан к
  стране аккаунта, платёжному профилю или cookies, смена IP не поможет.
- **Бесшовный перенос уже установленного TCP-соединения между egress-нодами.**
  При отказе egress текущее соединение обрывается, новое идёт через резерв.

Полный разбор ограничений: [`OPERATIONS.md`](OPERATIONS.md) и
[`SECURITY.md`](SECURITY.md).
