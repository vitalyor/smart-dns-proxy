# ADR 0006. Очередь задач в PostgreSQL вместо Redis

**Статус:** принято · **Дата:** 2026-08-26

## Контекст

Нужны отложенные и периодические задачи: загрузка списков, синтетические пробы,
чистка данных по сроку хранения. Нагрузка персональной установки — единицы задач
в минуту.

## Решение

Таблица `jobs` в PostgreSQL. Захват задачи — `UPDATE … WHERE id = (SELECT id …
FOR UPDATE SKIP LOCKED)`: одна транзакция, без гонок, с аренду по времени
(`lease_until`), повторами и экспоненциальной задержкой. Дедупликация —
уникальный `dedupe_key`.

## Альтернативы

- **Redis.** Ещё один сервис, ещё один том, ещё одна точка отказа и вторая
  модель устойчивости — ради нагрузки, которую БД не заметит.
- **Только in-process таймеры.** Задачи теряются при перезапуске и не переживают
  вторую копию панели.

## Последствия

- Меньше движущихся частей; задачи попадают в ту же резервную копию, что и
  остальное состояние.
- Захват задачи стоит одну запись в БД. При росте на порядки Redis можно ввести,
  но только после измерения.
- Просроченная аренда возвращает задачу в работу — упавшая панель не блокирует
  очередь навсегда.

## Тест

Чистка по сроку хранения и планировщики покрываются прогоном стенда:
загрузка списка выполняется через ту же очередь, что и по расписанию.
