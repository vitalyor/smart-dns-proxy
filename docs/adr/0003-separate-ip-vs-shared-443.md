# ADR 0003. Отдельные IP против общего 443

**Статус:** принято · **Дата:** 2026-08-26

## Контекст

DoH и управляемый HTTPS оба хотят TCP/443. На одном адресе одновременно занять
порт нельзя.

## Решение

Рекомендуемая топология — **два публичных IP**: `DNS_IP` для 53/853/443-DoH и
`PROXY_IP` для 443-прокси. Compose ноды принимает оба адреса из `.env`.

Для одного IPv4 поддержаны два пути: DoH на альтернативном порту (по умолчанию
8443) или внешний SNI-мультиплексор (nginx `ssl_preread`), конфигурация которого
приведена в OPERATIONS.

## Альтернативы

- **Встроить мультиплексор в data plane.** Ещё один компонент в пути трафика
  и ещё одна точка отказа ради экономии адреса, который стоит меньше доллара.
- **Только альтернативный порт.** Простой, но нестандартный порт режут
  корпоративные и гостевые сети.

## Последствия

- Попытка забиндить оба сервиса на один адрес невозможна по конструкции
  Compose: адреса задаются раздельно.
- Мультиплексор обязан отклонять пустой и неизвестный SNI, иначе health- и
  админ-имена уедут в прокси.

## Тест

Стенд использует один адрес и разные порты (443 прокси, 8443 DoH) и проверяет,
что оба слушателя поднимаются без конфликта. Проверка «SNI вне набора правил
отклонён» покрывает поведение `default`-ветки диспетчера.
