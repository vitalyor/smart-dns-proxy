# ADR 0005. Режимы аутентификации DNS и ограничение Android

**Статус:** принято · **Дата:** 2026-08-26

## Контекст

Android Private DNS принимает только имя хоста DoT и не передаёт произвольный
токен. Мобильный адрес источника меняется, поэтому список IP не работает.
Открытый резолвер быстро становится участником amplification-атак.

## Решение

Четыре режима, выбираются в настройках:

| Режим | Для кого | Чем защищён |
|---|---|---|
| `allowlist` | фиксированные адреса, VPN | список сетей |
| `doh-token` | клиенты с произвольным DoH-адресом | уникальный путь, в базе только хеш |
| `mtls` | управляемые клиенты | клиентский сертификат |
| `restricted-public-dot` | Android | строгие лимиты частоты и параллелизма |

По умолчанию — `allowlist` с пустым списком: резолвер отвечает `REFUSED`, пока
оператор явно не разрешит сети.

## Альтернативы

- **Обещать персональный DoT для Android.** Технически невозможно без поддержки
  со стороны ОС. Обещание было бы ложным.
- **Только DoH.** Отсекает Android, где Private DNS — самый удобный путь.

## Последствия

- `restricted-public-dot` честно назван контролируемо публичным резолвером;
  предупреждение показывается в профиле устройства и в настройках.
- Защита от amplification: лимит по префиксу клиента, потолок параллелизма,
  ограничение размера UDP-ответа с усечением, `minimal-responses` в Unbound.

## Тест

`TestDNSAccessControl` — клиент вне списка получает `REFUSED`.
Юнит-тесты лимитера покрывают выдачу и восстановление токенов ведра.
