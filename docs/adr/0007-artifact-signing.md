# ADR 0007. Подпись артефактов и ротация ключей

**Статус:** принято · **Дата:** 2026-08-26

## Контекст

Агент должен убедиться, что конфигурация пришла от его панели и не была
изменена, даже если транспорт скомпрометирован.

## Решение

Панель подписывает манифест ревизии ключом **Ed25519**; публичный ключ агент
получает при регистрации и хранит в `state.json`. Манифест содержит
`model_sha256`, список артефактов с их SHA-256, `min_agent_version` и
последовательный номер.

Агент проверяет по порядку: подпись → минимальную версию → принадлежность
артефакта своему `node_id` и роли → SHA-256 содержимого → локальную валидацию
структуры. Только затем — атомарное переключение симлинка.

Панель не считает ревизию применённой, пока агент не вернёт тот же SHA-256.

## Альтернативы

- **Полагаться только на mTLS.** Защищает канал, но не артефакт: скомпрометированный
  прокси или ошибка в хранилище пройдут незамеченными.
- **HMAC на общем секрете.** Общий секрет на всех нодах: компрометация одной
  ноды позволяет подделать конфигурацию для остальных.

## Последствия

- Ключ подписи входит в резервную копию. Его утрата означает, что ноды
  перестанут принимать новые ревизии, продолжая работать на last-known-good.
- Ротация ключа требует перерегистрации нод либо доставки нового публичного
  ключа отдельным каналом. Для персональной установки выбран первый путь.

## Тест

`TestManifestSignature` — валидная подпись принимается, изменённый манифест
отклоняется. `TestCompileIsDeterministic` — повторная сборка без изменений даёт
тот же хеш, поэтому подпись не «плавает».
