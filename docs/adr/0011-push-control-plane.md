# ADR 0011. Push-модель управления вместо pull

**Статус:** принято · **Дата:** 2026-08-27 · **Заменяет:** часть ADR 0007

## Контекст

Первая версия использовала pull: агент на ноде сам звонил панели, тянул
подписанные ревизии и применял их. У панели был входной mTLS-шлюз (8443), к
которому подключались ноды.

Реальное развёртывание идёт на уже существующий флот Remnawave: панель кочует
между серверами, а ноды стоят на месте. В pull переезд панели означал бы
переконфигурировать каждую ноду (они знают адрес панели). Плюс владелец уже
принял модель «панель ходит к нодам» по всему флоту (remnanode слушает панель),
так что аргумент pull «у ноды нет входного порта» для него уже неактуален.

## Решение

Панель сама подключается к нодам, как Remnawave.

- **Агент — HTTPS-сервер** на порту 3333 (HTTP/JSON поверх mTLS). Панель шлёт
  `POST /v1/config` при сборке ревизии и `GET /v1/health` раз в ~10 с. Нода
  наружу не звонит.
- **Enrollment — бандл.** Панель при создании ноды чеканит серверный сертификат
  ноды + ключ + якорь CA + отпечаток своего клиентского сертификата и отдаёт
  одним base64 (как `SECRET_KEY` у remnanode). Оператор вставляет бандл и
  вписывает адрес ноды в панели.
- **Доверие — mTLS + пин.** Нода пускает только клиента с отпечатком панели из
  бандла; в проде порт 3333 закрывается фаерволом на IP панели. Подпись конфига
  (ADR 0007) убрана: канал аутентифицирован, третий рубеж избыточен.
- **Транспорт — HTTP/JSON, не gRPC.** По каналу ходит крохотный JSON изредка;
  gRPC потянул бы тяжёлую зависимость и кодогенерацию без пользы (ponytail).
- **Кочующая панель.** Ключ CA и клиентский сертификат панели лежат в её
  state-томе и едут в бэкапе. Панель, поднятая из бэкапа на новом адресе,
  предъявляет тот же сертификат — ноды доверяют по отпечатку, не по IP. Переезд
  = восстановить бэкап + `ALLOW <новый IP>` на нодах + DNS-запись.

## Что не изменилось

Компиляция ревизий остаётся на панели, ноды тупые. Дата-плейн (dns-frontend,
sni-proxy, egress-relay, туннель ingress↔egress) не тронут: как конфиг доехал —
его не касается, применяется горячим релоадом через симлинк.

## Устойчивость (fail-open)

Нода хранит последний конфиг на диске и при перезагрузке поднимается из него,
не дожидаясь панели. Панель недоступна — нода обслуживает бесконечно: резолвер,
переставший отвечать, ломает пользователю весь интернет, что хуже слегка
устаревших правил. Примирение — по версии конфига в ответе о здоровье: панель
видит дрейф и дотолкивает.

## Цена

- На каждой ноде открытый (но аутентифицируемый и фаерволенный) порт управления.
  Владелец уже принял это по флоту Remnawave.
- Переезд панели не мгновенный, а в одну команду (скрипт правит DNS + ufw на
  нодах). Приемлемо против отказа от pull-автономии.

Проверено сквозным тестом в Docker (`scripts/lab-e2e.sh`, 33 проверки): push на
три ноды, две ingress с идентичным конфигом, multi-A failover при падении одной,
работа при выключенной панели, переподключение и повторный push после её
перезапуска.
