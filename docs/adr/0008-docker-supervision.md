# ADR 0008. Управление data plane без Docker socket

**Статус:** принято · **Дата:** 2026-08-26

## Контекст

Агенту нужно применить новую конфигурацию к работающим процессам. Обычный путь —
монтировать `/var/run/docker.sock` и перезапускать контейнеры. Docker socket
даёт практически root на хосте.

## Решение

**Socket не монтируется никуда.** Агент записывает ревизию в
`revisions/<id>/config.json` и атомарно переключает симлинк `active`.
Процессы data plane монтируют том только для чтения, опрашивают файл раз в две
секунды и подменяют скомпилированные матчеры in-process под мьютексом.

## Альтернативы

- **Монтировать socket.** Компрометация агента = компрометация хоста.
- **Ограниченный socket-proxy с allowlist эндпоинтов.** Ещё один компонент и
  всё ещё расширение поверхности атаки — ради перезапуска, который не нужен.
- **`systemd`-обёртка.** Привязывает решение к конкретному init и не работает в
  Compose-развёртывании.

## Последствия

- Применение ревизии не рвёт активные соединения: перезапуска нет вовсе.
- Задержка применения — до двух секунд опроса. Для конфигурации это несущественно.
- Изменение параметров, которые нельзя перечитать на лету (адреса слушателей),
  требует ручного перезапуска контейнера. Такие параметры вынесены в переменные
  окружения ноды, а не в ревизию.
- Опрос выбран вместо inotify намеренно: замена симлинка порождает события,
  которые легко пропустить или обработать дважды.

## Тест

`nodecfg` перечитывает файл по изменению mtime и размера; при невалидном
содержимом сохраняет предыдущую конфигурацию. В стенде выкат ревизии происходит
без перезапуска контейнеров, что видно по их аптайму.
