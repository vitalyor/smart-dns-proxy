# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [SemVer](https://semver.org/lang/ru/).

## [2.0.0] — 2026-08-27

Смена модели управления: **pull → push**, как в Remnawave. См. ADR 0011.

### Изменено (ломающее)

- Панель теперь сама подключается к нодам. Агент стал mTLS-сервером на порту
  **3333**; входной шлюз панели на 8443 удалён.
- Регистрация ноды — через **бандл** (base64 из панели, как remnanode SECRET_KEY)
  вместо одноразового токена. Нода наружу не звонит.
- Подпись конфига Ed25519 убрана: канал аутентифицирован mTLS, доверие держится
  на пине клиентского сертификата панели + фаерволе по IP.
- Здоровье ноды несёт только DNS-сигналы (версия конфига, запросов/с, отказы,
  Unbound, достижимость egress, дни до истечения серта); системная телеметрия
  живёт у оператора (Remnawave).
- `install-node.sh` принимает `--bundle`/`--role`; `install-panel.sh` больше не
  открывает 8443.

### Добавлено

- Кочующая панель: ключ CA + клиентский сертификат в бэкапе, переезд одной
  командой (DNS + ufw). Ноды доверяют по сертификату, не по IP.
- Мультиингресс: профили устройств перечисляют все ingress (Apple
  `ServerAddresses`, Windows primary+backup, Android multi-A на одном имени) —
  устройство само уходит с упавшей ноды.
- Сквозной тест доказывает две ingress с идентичным конфигом и failover при
  падении одной (`scripts/lab-e2e.sh`, 33 проверки в Docker).

### Мигрирование

Развёрнутого прода не было — переход чистый. Ноды пересоздаются через бандл.

## [1.1.0] — 2026-08-27

### Добавлено

- Единые уровни логирования (`debug`, `info`, `warn`, `error`) во всех пяти
  процессах. Уровень панели меняется в **Настройки → Логирование** и вступает
  в силу сразу; уровень нод уезжает со следующей ревизией и применяется горячей
  перезагрузкой, без перезапуска контейнеров.
- `LOG_LEVEL`, заданный на самом хосте, побеждает значение из панели — так
  отлаживают одну ноду, не трогая остальные.
- Подавление повторов: одинаковая строка уровня `info` и выше пишется раз в
  минуту, следующая несёт поле `suppressed` со счётчиком проглоченных повторов.
  Отключается через `LOG_THROTTLE=off`. На `debug` не действует.
- Ротация логов Docker во всех Compose-файлах: 3 × 10 МиБ на контейнер
  (`LOG_MAX_SIZE`, `LOG_MAX_FILE`). Раньше предела не было вовсе.
- Отладочные записи в ingress: что проксировано, через какую egress-ноду и что
  отклонено как неуправляемое имя.
- Раздел «Логи» в `OPERATIONS.md` и измеренные бюджеты памяти в
  «Бюджетах производительности».

### Изменено

- Успешные запросы к API больше не пишутся на уровне `info` — только на `debug`.
  Ответы 4xx пишутся как `warn`, 5xx как `error`. Опрос панели агентами каждые
  15 секунд давал больше сотни тысяч строк в сутки, в которых тонуло остальное.

### Исправлено

- Гонка данных: апстрим DNS переписывался горячей перезагрузкой одновременно с
  чтением из обработчиков запросов.
- Проверка «egress-relay отклоняет подключение без сертификата» в стенде читала
  вывод `openssl` на стороне клиента, где в TLS 1.3 отказ не виден; теперь
  проверяется счётчик отказов на самом relay.

## [1.0.0] — 2026-08-26

Первый выпуск.

### Data plane

- DNS frontend: обычный DNS на UDP и TCP, DoT, DoH (RFC 8484, GET и POST),
  синтез A и AAAA для управляемых доменов, подавление HTTPS и SVCB,
  ограничение частоты по префиксу клиента, четыре режима доступа.
- SNI proxy: чтение ClientHello без терминации TLS, проверка домена по активной
  ревизии, локальное переключение между egress-нодами с гистерезисом.
- Egress relay: взаимный TLS, allowlist доменов и портов из той же ревизии,
  повторная проверка адреса перед каждым подключением.
- Unbound: рекурсия, валидация DNSSEC, qname minimisation, serve-expired,
  защита от rebinding, доступ только из внутренней сети ноды.

### Control plane

- Панель: аутентификация Argon2id, TOTP с резервными кодами, RBAC,
  журнал аудита с автоматической редакцией секретов.
- Компилятор ревизий: один нормализованный набор правил управляет подменой DNS,
  маршрутизацией ingress и allowlist egress; детерминированная сборка,
  подпись Ed25519, остановка при конфликте доменов с равным приоритетом.
- Загрузчик списков: GitHub по репозиторию или прямой ссылке, произвольный
  HTTPS, встроенные пресеты, ручные списки; защита от SSRF, лимиты размера,
  порог массовых изменений, diff и подтверждение.
- Очередь задач в PostgreSQL: плановые обновления списков, синтетические пробы
  реального пути, чистка по срокам хранения.
- Веб-панель на React: обзор с живой схемой пути трафика, ноды, группы,
  сервисы, наборы правил с diff, ревизии, профили устройств, здоровье, аудит,
  настройки, быстрый старт. Тёмная и светлая темы.

### Агент

- Регистрация одноразовым токеном с закреплением CA панели по отпечатку.
- Получение ревизий по взаимному TLS, проверка подписи и SHA-256,
  атомарное применение переключением симлинка, откат на предыдущую версию.
- Защита от цикла перезапусков: не более трёх попыток за десять минут.
- Хранение минимум трёх последних ревизий; активная и предыдущая не удаляются
  даже при нехватке места.

### Эксплуатация

- Compose-профили для панели, ingress- и egress-ноды; полный контейнерный стенд
  с 21 сквозной проверкой (`make e2e`).
- Скрипты установки, обновления, резервного копирования и восстановления.
- OpenAPI 3.1, дашборд Grafana, правила оповещений, runbooks, десять ADR.

### Известные ограничения

HTTP/3 не гарантирован и по умолчанию отключён; сервисы с обязательным ECH не
поддерживаются; синтезированные ответы не несут подпись DNSSEC и никогда не
выставляют флаг AD; два DNS-адреса в настройках ОС не гарантируют переключение;
перенос установленного TCP-соединения между egress-нодами не выполняется.
Подробности — в README и `OPERATIONS.md`.
