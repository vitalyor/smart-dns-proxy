# Модель угроз и требования безопасности

## Что защищаем

1. **Приватность пользователя.** Payload трафика никогда не пишется. Полные
   DNS-запросы и клиентские IP по умолчанию не логируются: метрики агрегированы
   по сервису и ноде, идентичность клиента в лимитере хранится как префикс
   (/24 для IPv4, /64 для IPv6), а не как адрес.
2. **Контроль над инфраструктурой.** Ни ingress, ни egress не должны становиться
   открытым резолвером или открытым прокси.
3. **Целостность конфигурации.** Нода применяет только подписанный панелью
   манифест с совпадающим SHA-256 артефакта.

## Границы доверия

| Граница | Кто аутентифицирует кого | Механизм |
|---|---|---|
| Браузер ↔ панель | пользователь → панель | Argon2id + сессия в HttpOnly-cookie + TOTP |
| Агент → панель | нода → панель и панель → нода | mutual TLS сертификатами внутреннего CA |
| Первый контакт агента | панель → нода | отпечаток CA из команды установки (pinning) |
| Ingress → egress | ingress → egress | TLS 1.3 с клиентским сертификатом того же CA |
| Устройство → DNS | клиент → ingress | режим доступа: список сетей, токен в пути DoH, mTLS или публичный DoT с лимитами |
| Egress → origin | никто | обычный TLS клиента проходит насквозь, egress его не вскрывает |

Панель **не находится** в пути пользовательского трафика и не видит payload.

## Аутентификация панели

- Argon2id, параметры `t=3, m=64 MiB, p=4`, соль 16 байт (`panel/internal/auth`).
- Сессия — непрозрачный токен на 32 байта случайности; в базе только SHA-256.
- Cookie: `HttpOnly`, `SameSite=Lax`, `Secure` при публичном URL на HTTPS.
- CSRF: отдельный токен сессии, обязателен в заголовке `X-CSRF-Token` на всех
  изменяющих методах.
- TOTP (SHA-1, 6 цифр, шаг 30 с, допуск ±1 шаг) и десять одноразовых резервных
  кодов; секрет TOTP шифруется AES-256-GCM ключом из `PANEL_SECRET_KEY`.
- Лимит входов: после 10 неудач учётная запись блокируется на 15 минут.
  Ответ на несуществующий email занимает сопоставимое время.
- RBAC: `owner` > `operator` > `viewer` — проверяется на каждом маршруте.
- Смена пароля завершает все прочие сессии.

## Заголовки и CORS

`Content-Security-Policy: default-src 'self'` без `unsafe-eval`,
`frame-ancestors 'none'`, `base-uri 'none'`, `X-Content-Type-Options: nosniff`,
`Referrer-Policy: no-referrer`, HSTS при HTTPS. Кросс-доменные запросы
отклоняются: панель однодоменная.

## SSRF: две поверхности

**Загрузчик списков правил** (`panel/internal/fetcher`):

- только HTTPS;
- каждый DNS-ответ и каждое перенаправление проверяются против блок-листа
  диапазонов (loopback, RFC1918, CGNAT 100.64/10, link-local, `169.254.169.254`,
  IPv6 ULA и link-local, documentation-space);
- проверка повторяется в `Dialer.Control` непосредственно перед connect —
  это ловит DNS rebinding между резолвом и подключением;
- не более 5 перенаправлений; лимиты 10 МиБ сжатых, 50 МиБ распакованных,
  1 000 000 записей; таймауты на connect, заголовки и весь запрос;
- HTML-страница вместо списка отклоняется явно;
- опциональные `expected_sha256` и закреплённый корневой сертификат.

**Egress relay** (`node/relay`):

- destination принимается только из туннельного кадра, никогда от клиента;
- домен обязан присутствовать в allowlist активной ревизии, порт — в списке
  разрешённых;
- имя резолвится на egress через настроенный резолвер, каждый полученный адрес
  проверяется блок-листом, и проверка повторяется перед connect;
- при каждом новом резолве проверка выполняется заново — защита от rebinding.

Единственное исключение — `allow_private_destinations`, которое компилятор
проставляет только при `LAB_MODE=1`. Ревизия с этим флагом помечается в
манифесте и в интерфейсе, а на ноде выводится предупреждение при каждом
применении.

## Открытый резолвер и amplification

Публикация неограниченной рекурсии на UDP/53 запрещена по умолчанию:
`dns_access_mode` из коробки — `allowlist` с пустым списком, то есть резолвер
отвечает `REFUSED`, пока оператор явно не разрешит сети.

- Unbound слушает только внутреннюю docker-сеть, `access-control` по умолчанию
  `refuse`, `hide-identity`, `hide-version`, `minimal-responses`.
- DNS frontend ограничивает частоту по префиксу клиента и число одновременных
  запросов; при превышении — `REFUSED`, не `SERVFAIL`.
- Ответы UDP ограничены EDNS-размером клиента (не более 4096) и усекаются с
  установкой TC, что переводит злоупотребление в TCP.

**Android и персональность.** Private DNS передаёт только имя хоста DoT, без
токена. Режим `restricted-public-dot` честно называется контролируемо публичным
резолвером: защита — строгие лимиты и мониторинг, а не криптографическая
привязка к устройству. Панель показывает это предупреждение в профиле.

## Целостность ревизий

- Манифест подписывается Ed25519-ключом панели (`manifest-signing.key`, режим 0600).
- Агент проверяет подпись, `min_agent_version`, принадлежность артефакта своему
  `node_id` и роли, затем SHA-256 содержимого.
- Панель считает ревизию применённой только после отчёта агента с тем же
  SHA-256; несовпадение переводит развёртывание в `failed` с кодом `hash_mismatch`.
- Ошибка на любом шаге оставляет активной прежнюю конфигурацию.
- Нода может скачать только собственный артефакт: выборка идёт по `node_id`
  из клиентского сертификата.
- Отозванный сертификат блокируется немедленно — проверка идёт по отпечатку
  при каждом запросе.

## Изоляция контейнеров

- Многоступенчатые сборки, финальные образы без компилятора, `USER 10001`.
- `read_only: true`, `tmpfs` для `/tmp`, `cap_drop: [ALL]`,
  `no-new-privileges:true`; `NET_BIND_SERVICE` выдаётся только тем контейнерам,
  которым нужны привилегированные порты.
- **Docker socket не монтируется никуда.** Агент применяет ревизию, атомарно
  переключая симлинк `active`; процессы data plane сами перечитывают файл и
  обновляют матчеры in-process. Перезапуск контейнеров не требуется.
- Секреты передаются файлами и переменными окружения из `.env` с режимом 0600,
  не аргументами командной строки.
- PostgreSQL не публикует порт наружу.

## Ротация ключей

| Материал | Срок | Как обновить |
|---|---|---|
| Сертификат ноды | 90 дней | удалить `identity/` и перерегистрировать ноду новым токеном |
| Сертификат шлюза агентов | 10 лет | удалить `agent-gateway.crt/key` из тома панели и перезапустить |
| CA панели | 10 лет | смена требует повторной регистрации всех нод |
| Ключ подписи манифестов | бессрочно | входит в резервную копию; при утрате ноды перестанут принимать новые ревизии |
| `PANEL_SECRET_KEY` | по необходимости | после смены нужно заново включить TOTP |

Панель предупреждает за 14 дней до истечения сертификата ноды.

## Что писать в логи нельзя

Redaction применяется до записи в аудит и в журнал: поля `password`, `token`,
`secret`, `totp_secret`, `password_hash`, `ciphertext`, `recovery_codes`,
`private_key`, `key`, `authorization` заменяются на `***redacted***` рекурсивно,
включая вложенные объекты и массивы. В метках Prometheus запрещены qname,
клиентский IP и request id — используются только сервис, нода, транспорт и код
результата.
